# Smithtown Armed Security Proposal Chat Rules

Source document: `Smithtown_armed_security/markdown/Armed Security Guard Services - RFP 26-27-01 FINAL.md`

Use these rules for all proposal work in this chat.

- Treat Smithtown Central School District RFP #26/27-01, Armed Security Guard Services, as the controlling solicitation.
- Do not invent requirements, dates, staffing levels, insurance limits, pricing rules, forms, or evaluation criteria that are not supported by the RFP.
- When drafting proposal content, align every claim with the RFP's stated scope, qualifications, technical specifications, insurance requirements, required forms, and evaluation criteria.
- Preserve the RFP's required terminology: `Proposer`, `District`, `School District`, `Smithtown Central School District`, `armed security guard services`, and `RFP #26/27-01`.
- Do not qualify, limit, amend, omit, or take exception to RFP requirements unless the user explicitly asks to draft a clarification or exception.
- Proposal language should state compliance directly and avoid conditional phrasing that could make the response appear non-responsive.
- Assume the submitted proposal must include one original and two copies in a sealed envelope unless the user provides an addendum changing that instruction.
- Assume required signatures must be handwritten in ink where the RFP requires signatures and notarization where forms require notarization.
- If asked to produce a checklist, compliance matrix, proposal narrative, or executive summary, include the due date, submission address, contact, and major pass/fail requirements.
- If information is missing from the user's company materials, mark it as `TO BE PROVIDED` rather than guessing.
